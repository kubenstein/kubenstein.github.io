Technical Documentation
Kannon is a fun implementation of a cannon game with a trading twist, balancing the joy of building software with the seriousness of the trading and crypto industry. I built it as an interview pitch for Kraken's Senior Software Engineer - Frontend - Payments position.

This app was NOT vibe-coded. I use AI daily, and for this project I wanted to have old school fun myself, so I built everything from scratch. AI assisted with generating assets, proofreading English text, and consulting on the collision algorithm. Everything else was written by hand.Web AppKannon is a TypeScript web app built with Next.js. Although it is frontend-only, Next.js let me quickly set up a React-based development environment without worrying about low-level configuration and optimization. With Next.js and my fluency in web technologies, I was able to build the app over a weekend.

Core aspects of the app:

- An embedded cannon game
- A simple landing page that mirrors key elements of Kraken's official homepage
The GameLet's focus on the game, as it is definitely more interesting than the landing page.
The game is a React-based app in which fetched ETH/USD prices are used to form terrain. The terrain is made of Japanese candles commonly used in trading, directly referencing Kraken's trading experience.

A cannon and target are placed on this map, and the user's goal is to adjust the cannon's angle and power to hit the target.Game StateThe app leverages the useReducer hook and stores all game state in one place. Changes are applied by dispatching predefined actions. State and actions are exposed through React context, mimicking a familiarRedux-style architecture. This approach avoids fragmented state management, which can become error-prone and lead to race conditions.

It uses a render prop pattern to pass data to child components. This keeps information flowing in one direction from top to bottom, while child components dispatch actions upward. The game controller recalculates state and passes it back down to child components.

Fetching dataThe game uses real ETH/USD data fetched from the Kraken API. I thought this would be an interesting touch that makes each playthrough unique. I also wanted to integrate Kraken's API directly.

The data-fetching process follows these steps:

1) Fetch data from an unauthenticated GET endpoint
2) Reformat numeric values to floats
3) Remove buckets with zero volume
4) Trim the dataset to fit the map width
5) Normalize values to handle large price swings and keep the chart within the game frame
6) Reformat into the internal game candle shape

Kraken OHLC fetch, filtering, and candle normalization.TrajectoryEngineTrajectoryEngine is a separate engine that lives outside React and the game controller data flow. To achieve 60 FPS, this part should not be driven by React rendering. TrajectoryEngine receives initial data and reacts to updated angle and power values, but all calculations and bullet position updates are done in plain JavaScript, with movement rendered via GPU-accelerated CSS transformproperties. The engine models each candle as a rectangular obstacle in 2D space, and the bullet is launched using a velocity vector derived from angle and power.
this.bullet = deepCopy({
  position: this.cannon,
  velocity: {
    x: Math.cos(this.angle) * this.power,
    y: Math.sin(this.angle) * this.power,
  },
});
Bullet initialization from angle and power.The system then enters the rAF loop.
The game loop performs several standard operations per frame, except this game has no direct user input during projectile flight:

0) Store the previous bullet position for more reliable collision detection
1) Move the bullet according to its velocity vector and gravity
2) Check collision with the target
3) Check collisions with obstacles
4) Check collisions with map boundaries
5) Re-render bullet position
private gameLoop(deltaTime: number) {
  // 0)
  const prevBulletPosition: Point = { x: this.bullet.position.x, y: this.bullet.position.y };

  // 1)
  this.bullet.velocity.y -= this.gravity * deltaTime;
  this.bullet.position.x += this.bullet.velocity.x * deltaTime;
  this.bullet.position.y += this.bullet.velocity.y * deltaTime;

  // 2)
  if (this.segmentCollides(prevBulletPosition, this.bullet.position, this.target)) {
    this.enabled = false;
    this.onTargetHit();
    return;
  }

  // 3)
  for (const obstacle of this.obstacles) {
    if (this.segmentCollides(prevBulletPosition, this.bullet.position, obstacle)) {
      this.enabled = false;
      this.onObstacleHit(obstacle.id);
      return;
    }
  }

  // 4)
  if (this.bullet.position.x > this.rightBoundary || this.bullet.position.y < this.bottomBoundary) {
    this.enabled = false;
    this.onOutOfMap();
    return;
  }

  // 5)
  this.render();
}
Per-frame simulation and collision checks.Collision detection algorithmCollision detection runs on every frame, but with high bullet velocity it is possible for the bullet to be in front of an obstacle on one frame and already behind it on the next. This problem is called "tunneling", and it is a common issue in games. That's why, instead of checking whether a single point is inside an obstacle, we check whether the segment formed by the previous and current bullet positions crosses any obstacle edge.

Below is an example of how to calculate whether two segments cross. In our case, one segment represents the bullet's movement and the other represents an obstacle edge. In the game, this process is repeated for each edge of each obstacle on every frame.
This algorithm is called the "orientation" method. Two segments cross if:

"For each segment, we check whether the endpoints of the other segment lie on opposite sides of it."
private segmentsCross(segA: Segment, segB: Segment) {
  const segAStartSideOfSegB = this.sideFromSegment(segB, segA.start);
  const segAEndSideOfSegB = this.sideFromSegment(segB, segA.end);
  const segBStartSideOfSegA = this.sideFromSegment(segA, segB.start);
  const segBEndSideOfSegA = this.sideFromSegment(segA, segB.end);

  const segAPointsAreOnOppositeSidesOfSegB = segAStartSideOfSegB > 0 && segAEndSideOfSegB < 0;
  const segAPointsAreOnOppositeSidesOfSegBFlipped = segAStartSideOfSegB < 0 && segAEndSideOfSegB > 0;

  const segBPointsAreOnOppositeSidesOfSegA = segBStartSideOfSegA > 0 && segBEndSideOfSegA < 0;
  const segBPointsAreOnOppositeSidesOfSegAFlipped = segBStartSideOfSegA < 0 && segBEndSideOfSegA > 0;

  // check if segments cross eachother
  if (
    (segAPointsAreOnOppositeSidesOfSegB || segAPointsAreOnOppositeSidesOfSegBFlipped) &&
    (segBPointsAreOnOppositeSidesOfSegA || segBPointsAreOnOppositeSidesOfSegAFlipped)
  ) {
    return true;
  }

  // check if segments touch eachother at endings
  if (segAStartSideOfSegB === 0 && this.onSegment(segB, segA.start)) return true;
  if (segAEndSideOfSegB === 0 && this.onSegment(segB, segA.end)) return true;
  if (segBStartSideOfSegA === 0 && this.onSegment(segA, segB.start)) return true;
  if (segBEndSideOfSegA === 0 && this.onSegment(segA, segB.end)) return true;

  return false;
}
