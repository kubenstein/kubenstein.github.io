Technical Documentation
Qualstamp is a fun yet fully functional, AI-powered Solidity auditing tool. It's built with Next.js, Socket.io, and the opencode CLI running in Docker. I built it as an interview pitch for Quantstamp's Full-Stack Engineer - AI Security Products role — Jakub Niewczas.

Web AppQualstamp is a TypeScript web app built with Next.js. Even though it has only one page, Next.js let me avoid low-level React setup and build tooling, so I could build the whole app over a weekend. For real-time updates, I used Socket.io, which I've used extensively for WebSocket applications. The web app lets users paste a GitHub repository URL containing Solidity contracts, start the audit process, and view results in real time as they are generated by the backend service.

Client/server communication is handled via Socket.io. The audit itself is executed by running the opencode CLI inside Docker.
export default function wsHandler(serverIO: ServerIO) {
  serverIO.on('connection', socket => {

    socket.on('audit-github-repository', ({ gitRepoUrl }) => queueAuditUsecase({ socket, gitRepoUrl }));
    socket.on('get-queue-length', () => provideQueueLengthUsecase({ socket }));
  });
}

Code responsible for rendering the audit report using the Markdown component.BackendThe backend lives inside the same Next.js app and exposes three WebSocket-facing use cases: queueAuditUsecase(), provideQueueLengthUsecase(), and cleanQueueUsecase(). I like to encapsulate each use case in an explicit unit of code (usually a function), so there's a clear place where business logic lives. Depending on the app, validation and other concerns can also fit naturally inside a use case.
import { Socket } from 'socket.io';
import auditGithubRepository from '../../lib/audit-github-repository.js';

type Params = {
  socket: Socket;
  gitRepoUrl: string;
};

export default async function usecase({ socket, gitRepoUrl }: Params): Promise<void> {
  if (!socket.connected) return;

  socket.emit('output', `Start audit...\n`);
  const { code } = await auditGithubRepository({
    requester: socket.id,
    gitRepoUrl,
    onData: (data: string) => socket.emit('output', data),
  });
  socket.emit('output', `Command exited with code ${code}\n`);
}
Use case that runs the audit and streams output in real time.The audit pipeline begins in queueAuditUsecase(), which queues the request so audits run one at a time. To keep things simple, the queue is implemented in memory using a basic array. When a request reaches the front of the queue, it runs auditGithubRepositoryUsecase().

That use case delegates to the auditGithubRepository() library function to perform the actual audit. This function clones the GitHub repository, runs opencode inside a Docker container, and streams output back via a callback.
export default function auditGithubRepository({ requester, gitRepoUrl, onData }: Params): Promise<Result> {
  return new Promise(resolve => {
    try {
      const process = spawn('./audit-github-repository-runner.sh', [requester, gitRepoUrl]);
      process.stdout.on('data', data => onData(data.toString()));
      process.stderr.on('data', data => onData(data.toString()));
      process.on('close', code => resolve({ code, error: null }));
    } catch (e) {
      resolve({ code: -1, error: (e as Error).message });
    }
  });
}
Library function that spawns the Docker-based audit runner and streams output.DockerThe actual Docker invocation is a bash script. It builds the image and runs the container with the correct parameters.
#!/bin/bash

# stop on error
set -e

REQUESTER=$1
GIT_REPO_URL=$2

DOCKERFILE=$(cat <<FILE
  FROM alpine:latest
  WORKDIR /usr/src/app
  RUN apk update \
   && apk add --no-cache bash git curl libstdc++ \
   && curl -fsSL https://opencode.ai/install | bash \
   && git config --global --add safe.directory /usr/src/app
FILE
)

echo "${DOCKERFILE}" | DOCKER_CLI_HINTS=false docker build -t qualstamp-runner -

docker run --rm \
  --label requester=$REQUESTER \
  -e GIT_REPO_URL="${GIT_REPO_URL}" \
  qualstamp-runner \
  bash -l -c "
    AUDIT_PROMPT='...'
    echo \"- Cloning repository: \$GIT_REPO_URL\"
    git clone \"\$GIT_REPO_URL\" /usr/src/app

    echo \"- Starting analysis with opencode...\"
    opencode run \"\$AUDIT_PROMPT\"
  "
Bash script that builds the runner image and executes the audit in a container.The AUDIT_PROMPT in the script is the prompt passed to the AI agent performing the audit. It contains the carefully crafted instructions and the desired report format.

Each audit run is performed in a fresh Docker container, ensuring a clean environment for every execution. After the audit is complete, the entire container, along with all its data, is removed thanks to the--rm flag in the docker run command.

We also tag each container with a requester label containing the Socket.io socket ID. This tag is used to instantly kill and remove the container if the user disconnects before the audit is complete.InfrastructureThe app is deployed to Fly.io. Unfortunately, Fly.io (like many similar platforms) does not support Docker-in-Docker, which is a critical part of this app's design. To solve this, the Docker daemon runs on a small VPS on Vultr, and every Docker command issued from Fly.io is executed remotely via the DOCKER_HOST environment variable (configured with an SSH connection string).
